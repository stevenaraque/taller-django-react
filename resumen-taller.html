Guía del taller: Django + React

Taller Full-Stack de 3 días · 18 horas — los estudiantes construyen, paso a paso y con premios, una app de lista de tareas completa: React en el navegador conversando con una API REST en Django, respaldada por PostgreSQL.

3 sesiones 18 horas 15 mini-tareas 1 reto final con premio mayor Base: Postgres taller_django_react

1 El resultado final — lo que va en la pantalla al terminar

⚛️ Frontend (localhost:5173)

Una SPA en React + Vite donde cada estudiante ve su propia app lista para presumir: la escriben, la conectan y la decoran ellos.

  • Formulario para crear tareas (POST)
  • Lista que pinta el JSON de la API
  • Completar, editar y eliminar cada tarea
  • Filtro lógico: ver solo pendientes
  • Estilos propios (reto final)

🚀 Backend (localhost:8000)

Una API REST con Django REST Framework construida por ellos: modelo, serializador y CRUD completo.

  • Modelo Tarea en PostgreSQL
  • Juguete gratis: el Django Admin como panel
  • Operaciones reales: GET / POST / PATCH / DELETE
  • Monitor social disponible: el Cronometro mide los ms de la consulta

🐘 Datos (PostgreSQL 18)

Base de datos taller_django_react: las tareas quedan guardadas de verdad aunque cierren todo — esa es la respuesta a la pregunta de apertura del taller.

  • Django 6.1 conectado vía psycopg
  • El modelo se migró con makemigrations + migrate
  • SQLite local quedó a un lado: hoy toca Postgres

2 Por qué enseño esto — el argumento de venta

❓ arranca por la pregunta

"Cierras la app: ¿dónde quedaron tus tareas?" — la sesión 1 apuesta a que salgan sentenciarlo ellos mismos (A pantalla / B navegador / C servidor + BD) y se respondan en los 3 días con la app convertida en evidencia.

🧠 democratiza el "full stack"

Ver que un puerto pide (React), otro responde (Django) y otro guarda (Postgres) rompe la idea mágica: son 3 procesos normales que se hablan por HTTP + JSON.

🎮 aprenden haciendo, no copiando

La regla del juego: "funciona y sabes decir qué hiciste y por qué". Los instructores dan pistas, no respuestas; quien gana el bombombún es quien explica.

3 El mapa de las 3 sesiones

🐍 DÍA 1 — Backend con DRF
Horario: arranque y entorno (2h) → mini-tareas 1 a 5 → cierre (15 min) Meta: una API que responde JSON Stack: venv + Django 6.1 + DRF + PostgreSQL
  • Mini 1Crear el modelo Tarea y correr las migracionesmodelos CharField + BooleanField; en la plantilla además descripcion y creada; ORM = makemigrations + migrate
  • Mini 2Poblar datos desde el Django Adminadmin.site.register(Tarea) + createsuperuser + crear 3 registros; de regalo ya hay superuser steven
  • Mini 3Crear el TareaSerializerModelSerializer con fields; el traductor de Python → JSON → Python
  • Mini 4Vista GET: ver el JSON crudo en el navegadorapi/tareas/; en la plantilla es un ModelViewSet + router (se explica como versión simplificada con @api_view)
  • Mini 5Vista POST: guardar y verificarcrear una tarea y reconsultar — primer ciclo CRUD completo
⚛️ DÍA 2 — React y conexión
Horario: setup de React y CORS (2h) → mini-tareas 6 a 10 → cierre (15 min) Meta: React hablando con Django sin errores en consola Stack: Vite :5173 + fetch + useState + django-cors-headers
  • Mini 6Primer render: título gigante en :5173componentes + JSX; la app es un árbol: App → Formulario, ListaTareas, Cronometro
  • Mini 7¡El Jefe CORS!demo en vivo: el navegador bloquea la respuesta de :8000, se instala/activa corsheaders; objetivo: fetch sin error en consola (F12)
  • Mini 8useState + map: pintar los títulos del JSONlas claves del estado en React + key en la lista
  • Mini 9Formulario controladovalue + onChange ligado al estado
  • Mini 10POST final desde Reactfetch con método POST + JSON; crear y verla al recargar
✨ DÍA 3 — CRUD completo y reto final
Horario: mini-tareas 11 a 14 → Reto Final (1h) → cierre y premio (1h) Meta: la app completa y con estilo Extra: reto social "El Velocista" (medir quién tiene la consulta más rápida)
  • Mini 11Estado dinámico: crear sin recargar la páginaReact suma la tarea a su estado tras el POST
  • Mini 12DELETE: eliminar tareaDELETE a api/tareas/id/ + quitarla del estado
  • Mini 13PUT / PATCH: marcar como completadacompletada cambio en la BD + reflejo en pantalla
  • Mini 14Filtro lógico de pendientestareas.filter((t) => !t.completada)
  • Mini 15🏆 EL RETO FINAL: estilosCSS, Tailwind o Bootstrap; la mejor interfaz la vota el grupo — premio mayor
💡 Cómo aprenderán cada tema (las 5 fases): 1️⃣ Problema real de la app → 2️⃣ Pregunta (proponen antes de explicar) → 3️⃣ Explicación línea por línea → 4️⃣ Mini-tarea (modifican y deciden) → 5️⃣ Verificación (leer errores con F12). Gamificación: una mini-tarea = un bombombún para el primero que la logre y la explique; el reto final lo vota todos.
